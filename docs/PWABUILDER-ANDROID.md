# Cabana Android release settings

The Play Store package is a Trusted Web Activity generated by PWABuilder. The
website cannot add Android permissions to an already-published AAB; these
settings must be selected when generating the next Android package.

Use the existing application id `africa.cabana.app`, host `cabana.africa`, and
start URL `https://cabana.africa/?utm_source=pwa`. In PWABuilder's Android
options enable both of these delegations:

- **Notification delegation**: enabled. This adds `POST_NOTIFICATIONS` and
  routes web push through the Cabana app instead of Chrome.
- **Location delegation**: enabled. This adds the Android location permission
  and lets `navigator.geolocation` use the app permission while the TWA is
  running.

Build a new signed AAB with an incremented version code and upload it as an
update to the existing Play listing. Keep the same package id and signing
identity. Installing an APK signed with a different key does not test the
Play build's signing relationship.

- hybrid PQC certificate: `91:3B:49:7E:A9:D4:28:CC:52:9C:A3:F8:93:2D:7C:B0:82:15:34:17:DE:01:54:06:F2:84:4F:52:1B:4A:5A:8B`

All three, plus the development certificate used by the supplied APK, are
now in `.well-known/assetlinks.json`. Publish the website before releasing the
new AAB. Google recommends registering every certificate when quantum-ready
hybrid signing is enabled.

After publishing, verify:

1. `https://cabana.africa/.well-known/assetlinks.json` returns JSON with
   `Content-Type: application/json`.
2. The JSON contains package `africa.cabana.app` and the Play app-signing
   SHA-256 fingerprint.
3. The new AAB is installed from Play after the website change.

With those two pieces in place the app opens fullscreen, Android owns the
notification permission, and Android can own the location permission. Chrome
may still show notifications for ordinary browser tabs; that is expected.
